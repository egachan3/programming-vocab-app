## 1. サービス概要（※最後に書いてOK）

- Ruby / Rails 初学者向けのプログラミング学習用単語帳アプリです。
学習する上で必要な基礎知識をカテゴリ別に整理して学べます。
理解状況を記録しながら、反復学習しやすい構成を提供します。
- Ruby / Rails 初学者が、基礎知識を忘れてしまい、何度も調べ直してしまう課題を解決します。
また、「何を覚えるべきか」で迷う負担に対して、整理済みの単語を単語帳形式で学べる仕組みを提供します。

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

RubyやRuby on Railsの学習を進める中で、MVCやルーティングなどの用語に加え、関数やクラスの意味・役割も曖昧になり、何度も教材やメモを見返すことがありました。
そのたびに学習の流れが止まり、「理解したつもりでも定着していない」と感じたことが、このアプリを考えたきっかけです。

---

### 2-2. なぜそれが「気になった」のか

私は、学んだことを曖昧なままにして進めることに不安を感じやすく、きちんと理解して記憶に定着させたいと考えています。
そのため、用語や関数、クラスを覚えたつもりでも後から思い出せないと不安になり、学習のモチベーションが下がることがありました。
基礎が定着していない状態では、その先の学習にも自信を持てないため、この問題が特に気になりました。

---

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

学習中に、用語や関数、クラスの理解が曖昧なままになり、復習や実装のたびに何度も調べ直してしまうことです。

---

### 3-2. 本当に解決したい課題は何か　

- 用語の意味が曖昧だと、教材の内容やエラー内容を正しく理解しづらいから
- 理解が浅いまま学習を進めることになり、実装や復習の効率が下がるから
- 「自分は理解できていない」という感覚が積み重なり、学習への自信や継続意欲が下がるから

→ 本当に解決したい課題：プログラミング初学者が、基礎用語への理解不足によって学習効率や自信を失ってしまうこと。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

年齢設定：
  - 年齢：20代〜30代
  - 理由：就職・転職・スキルアップを目的に、限られた時間でプログラミング学習を進める人が多く、基礎用語を効率よく定着させたいニーズが高いと考えたため

生活・状況設定：
  - 生活・状況：プログラミングスクール受講生、独学でWeb開発を学ぶ人、働きながら学習している初学者
  - 理由：学習時間が限られている中で、毎回教材や検索に戻る負担が大きいため、短時間で反復復習できる仕組みが役立つから

環境設定：
  - 環境：PCで学習しつつ、スキマ時間はスマホでも復習したい人
  - 理由：プログラミング学習はPC中心になりやすい一方、復習は通勤時間や待ち時間にも行いたいため、単語帳形式で手軽に見返せることが継続のハードルを下げるから

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)

- このサービスは、学習中に「同じ用語を何度も調べてしまう」「理解したはずなのに説明できない」と感じたときに、使ってみようと思われるサービスです。
- ユーザーは最初に登録し、あらかじめ用意されたRuby / Railsの単語帳を選ぶ、または自分で単語帳を作成します。
その後、1日5分程度でも学習できるように、問題を解いたり、覚えた・覚えていないを選択しながら復習を進めます。

- 継続して使われる理由は、以下の3つです。
1. 短時間で学習できる
2. 学習履歴に応じて「復習すべき単語」がわかる
3. 基礎用語が定着することで、普段の学習や実装が少しずつ楽になり、達成感も得られる

単なる暗記ツールではなく、日々のプログラミング学習を支える補助線として継続利用されることを想定しています。

## 8. このアプリの懸念点とその対策
※最低1つは必ず書いてください。

このアプリが**うまくいかない可能性**と、
それに対して**どう向き合おうとしているか**を書いてください。

### 懸念点①

- 何が問題になりそうか：ユーザーが最初だけ使って、継続しない可能性がある
- なぜそう思うか：暗記アプリは必要性を感じても、日々の利用習慣に組み込まれないと離脱しやすいから
- そのために考えている対策：1回の学習を短く終えられる設計にすること、学習履歴から復習すべき単語を自動で提示すること、進捗が見えるようにして達成感を持てるようにすることを考えています。

- 何が問題になりそうか：単語の意味を暗記するだけで、実装力には直結しないと思われる可能性がある
- なぜそう思うか：プログラミング学習では「手を動かすこと」が重視されやすく、暗記学習の価値が伝わりづらいから
- そのために考えている対策：単語の定義だけでなく、コード例や使用場面も合わせて表示し、実装と結びつけて理解できる設計にしたいと考えています。

## 9. 今後の展開・発展の方向性

### 観点（すべて答えなくてOK）

- 苦手な単語を自動で見返せると便利、短時間で復習でき学習習慣に組み込みやすいから
- 用語・関数・クラスの理解が定着する、わからない事を調べた時に理解しやすくなる、自信を持てる
- 復習優先度の最適化、学習段階に応じたおすすめ出題
- ユーザー作成単語帳の共有、人気単語帳の閲覧
- 学習履歴をもとに、復習すべき単語を自動で提示し、継続しやすい仕組みにする

### 今考えている発展案

- 機能追加の方向性：忘却曲線を意識した復習スケジュール、AIによる単語説明補助、ユーザー作成単語帳の共有機能、他言語や実装に必要な知識の追加
- UI・体験の改善：次に復習すべき単語の提示、学習進捗の可視化
- 機能以外の工夫：初学者が「何から覚えればいいか」で迷わないように、学習レベル別のおすすめ単語セットを用意する

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク：Ruby on Rails 8.1
- フロントエンド：Hotwire（Turbo / Stimulus）/ TailwindCSS
- DB：PostgreSQL
- デプロイ先：Render
- 認証：Devise / OmniAuth
- 使用予定ライブラリ： Kaminari / Ransack

---

### 10-2. 技術選定の理由

- フロントエンドには Hotwire を用い、カテゴリ切り替えや一覧更新を快適に行えるようにしたいと考えています。
認証には Devise、DB には PostgreSQL、UI には Tailwind CSS を採用し、学習アプリとして必要な機能を実装しやすく、学習コストの低いMVPに向いた構成にしたいと考えています。
- 今回チャレンジしたい点：単語・カテゴリ・学習履歴のデータ設計、Hotwire を使った部分更新、認証機能の実装に挑戦したいです。
また、学習しやすいカテゴリ表示や無限スクロール風UIなど、継続しやすい体験づくりにも取り組みたいと考えています。
- 不安な点：今後の機能追加を見据えたときに、最初のデータ設計で拡張性を十分に確保できるか不安があります。
また、使ったことない技術を使うので、MVPリリースに必要な実装についても不安です。
